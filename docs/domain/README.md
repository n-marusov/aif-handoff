# Domain-Driven Design (DDD) — AIF Handoff

В этой директории собраны DDD-артефакты для **AIF Handoff**: автономной системы управления задачами с Kanban-интерфейсом и runtime-нейтральными AI-оркестраторами.

Фокус доменной модели: жизненный цикл задачи, оркестрация исполнения через runtime-профили, правила владения/передачи задач и интеграционные границы (GitHub/GitLab, MCP, внешние runtime-провайдеры).

> **Статус:** 4 ограниченных контекста, 8 агрегатов и 18 доменных событий как инженерный baseline. Модель отражает текущие границы `@aif/shared`, `@aif/data`, `@aif/runtime`, `@aif/api`, `@aif/agent`.

## Принципы оформления DDD-артефактов

### Именование

1. **Файлы** — английские имена в `kebab-case`.
2. **Контексты** — семантический ID в `kebab-case`.
3. **Агрегаты/сущности/VO** — `PascalCase`, в тексте — в backticks.
4. **Доменные события** — `PascalCase`, внешние ключи событий — `dotted-kebab-case`.
5. **Язык документации** — русский; технические идентификаторы оставляются на английском.

### Структура

Каждый документ должен быть сканируемым:

- таблицы для инвентаризации сущностей/событий/связей;
- краткие списки инвариантов и границ;
- явные перекрёстные ссылки на смежные артефакты.

## Принципы моделирования для AIF Handoff

1. **Task lifecycle — ядро домена.** Ценность системы определяется корректным прохождением фиксированных стадий (`Backlog → Planning → Improve → Plan Review → Implementing → Verify → Review → Done → Accepted`) и автоматизацией переходов.
2. **Runtime — стратегический порт, не бизнес-ядро.** Провайдеры (Claude/Codex/OpenRouter/OpenCode) внешние; модель фиксирует capability-контракт, а не SDK-детали.
3. **Ownership и automation разделены.** Владелец задачи (human/AI) и `autoMode` — независимые оси политики.
4. **Инварианты удерживаются внутри агрегатов.** Межконтекстная согласованность достигается событиями и application-layer оркестрацией.
5. **DB boundary обязательна.** Доступ к БД из `api`/`agent`/`runtime` только через `@aif/data`.
6. **Интеграции через ACL/антикоррупционные слои.** Внешние модели GitHub/GitLab/MCP/runtime-провайдеров переводятся в внутренние команды/события.
