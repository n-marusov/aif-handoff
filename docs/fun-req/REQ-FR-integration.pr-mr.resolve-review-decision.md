# REQ-FR-integration.pr-mr.resolve-review-decision: Обработка решения ревью по PR/MR

**Приоритет:** P1

**Ключевая функция:** HF11.1 Синхронизация с Issues, HF11.2 Публикация PR/MR (гейт HF4.4 Plan Review Gate)

**Источник:** [UC-integration.pr-mr.resolve-review-decision](../use-cases/UC-integration.pr-mr.resolve-review-decision.md), BR-inference.git.review-decision-precedence, BR-trigger.automation.plan-review-gate, BR-fact.git.vcs-workflow

**Статус:** proposed

**Класс:** as is

**Канал:** Schedule/Agent (VCS REST API)

**Описание:** При сверке связанного PR/MR система считывает состояние PR/MR, состояние одобрений, статусы CI и записи ревью, определяет действующее решение ревьюера (последнее неотозванное) и применяет его к задаче один раз: одобрение открывает гейт плана, запрос изменений возвращает задачу на доработку, слияние принимает результат — в том числе когда задача ещё не завершила стадию ревью. Отозванное одобрение и повторная сверка состояние задачи не меняют.

**Критерии приёмки:**

1. Сверка считывает состояние PR/MR (открыт / закрыт / слит), состояние одобрений и статусы CI, и сохраняет их в привязке PR/MR задачи.
2. Статус ревью считается одобренным только при наличии фактического одобряющего; формальный признак одобрения без одобряющих одобрением не считается.
3. Действующим решением ревьюера считается последнее по времени решение, не отозванное явным отзывом или сбросом одобрений при обновлении содержимого ветки.
4. Задача в стадии плана при действующем одобрении переходит в реализацию с признаком утверждённого плана.
5. Задача в стадии плана при запросе изменений возвращается к планированию с сохранением обратной связи ревьюера как входа для доработки плана.
6. Задача в стадии ревью или завершённая при запросе изменений возвращается в реализацию с пометкой о переработке и сбросом состояния фиксации изменений.
7. Слияние PR/MR принимает результат: задача в стадии ревью проходит через завершение стадии в принятое состояние за одну сверку, а рабочее дерево задачи освобождается.
8. PR/MR, закрытый без слияния, приостанавливает задачу и не продолжает конвейер.
9. При отозванном или сброшенном одобрении переход в реализацию не выполняется, даже если ранее такое решение ревьюера было выдано.
10. Когда необработанных решений накопилось несколько, применяется последнее по времени; более ранние решения не применяются.
11. Отметка об обработанном решении сохраняется только после успешного перехода задачи.
12. Если переход отвергнут из-за конкурентного изменения состояния задачи, отметка не сохраняется, ошибка фиксируется в журнале, а решение применяется при следующей сверке.
13. Повторные сверки с тем же решением ревьюера не изменяют состояние задачи (идемпотентность обработки решений).
14. При отсутствии связанного PR/MR сверка не изменяет состояние задачи.
