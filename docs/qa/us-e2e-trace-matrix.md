# US ↔ E2E Trace Matrix

> Каноническая карта соответствия сценариев пользовательских историй (US) сквозным E2E-тестам.
> Дата актуализации: 2026-09-21 (план «US + E2E Refactor»).
> Теги: `@core-e2e` | `@requires-llm` | `@env-dependent`.

## Legend

- **Primary E2E layer** — слой, которому принадлежит полная oracle-проверка сценария:
  - **API** — state machine, владение, семантика синхронизации, негативные переходы
    (REST + WS напрямую в сервис `api`);
  - **GUI** — UX-поток, рендеринг/взаимодействие, пользовательские переходы
    (Playwright browser против `web`).
- **Secondary smoke/trace** — второй слой держит не более smoke-проверки, ссылающейся
  на primary-тест (без дублирования полной oracle-валидации).
- **Теги**:
  - `@core-e2e` — детерминированный сценарий, LLM не нужен (`e2e:core`);
  - `@requires-llm` — требует `AIF_LLM_INTEGRATION=1` + включённый runtime-профиль
    (`e2e:llm`; в core-контуре пропускается с причиной);
  - `@env-dependent` — требует особого окружения (например, `PARTICIPANTS_MODE_ENABLED=true`
    или контролируемой внешней VCS-платформы).

## Correlation IDs (P2.1)

Для снижения MTTR при падениях E2E вводится схема корреляции `testId`/`traceId`
(хелпер: `packages/web/e2e/shared/trace.ts`):

- **`traceId`** — один на Playwright-ран (worker-процесс). Источники: env
  `AIF_E2E_TRACE_ID` (CI передаёт для всей полосы прогона) или авто-генерация
  `e2e-<epoch>-<rand>` при первом импорте.
- **`testId`** — стабильный slug заголовка теста (например, `L-10-full`).
  Логируется как `[e2e:<testId>] [trace:<traceId>] <step> <details>`.
- **Проброс в API-запросы**: спектры ходят через `request.*` Playwright; для полного
  проброса добавить заголовок `X-E2E-Trace-Id: <traceId>` в хелперы `api/common.ts` /
  `gui/common.ts` (см. `docs/qa/e2e-api-testing.md` — тема correlation headers).

### Mapping: test step ↔ log event

| Test step                       | API request / event                         | Log event (поиск)                                              |
| ------------------------------- | ------------------------------------------- | -------------------------------------------------------------- |
| Создание изолированного проекта | `POST /projects` (201)                      | `[e2e:<testId>] project created` + `createProject` в api-логах |
| Подключение GitLab              | `PUT /projects/:id/gitlab` (200)            | `connectGitLabViaUi/Api`; `gitlab:connected`                   |
| Синхронизация                   | `POST /projects/:id/gitlab/sync`            | `[e2e:<testId>] sync started`; `GitLab sync` (data:gitlab)     |
| Импорт задачи                   | `GET /projects/:id/gitlab` → `entry.taskId` | `GitLab issue synchronized {taskId}` (data:gitlab)             |
| Переход статуса                 | `GET /tasks/:id` → `status`                 | `task:moved {fromStatus→toStatus}` (WS/notifier)               |
| Публикация plan-MR              | `POST .../publish-plan`                     | `plan_review` MR mode; `GitLab merge request mode updated`     |
| Merge MR                        | `PUT .../merge_requests/:iid/merge`         | `done → accepted` в sync-маршруте (`gitlab-routes`)            |
