# BR-trigger.automation.runtime-limit-gate — Гейт лимитов провайдера

> Потребление runtime-ресурсов учитывается; при приближении к лимиту или его достижении новые запуски блокируются до сброса окна лимита.

## Правило

Каждый вызов runtime учитывается (токены, стоимость, длительность). Состояние лимитов нормализуется и сохраняется, чтобы все процессы видели единую картину. Если профиль достиг лимита провайдера, новые запуски блокируются до момента сброса окна лимита.

## Детализация

- Учёт ведётся по каждому вызову и персистентно хранится; история использования доступна.
- Задача может быть превентивно переведена в `Blocked (External)` до жёсткого отказа провайдера.
- Блокировка применяется, если провайдер сообщил о блокировке с будущим временем сброса, либо если достигнут порог предупреждения точного лимита.
- Возобновление заблокированной задачи происходит по пути `Blocked (External)` + время повтора при наступлении сброса.
- Публикация плана не потребляет токены провайдера и исключена из гейта лимитов.
- Превентивная блокировка применяется только если задача всё ещё в ожидаемом состоянии в момент записи.
- Гейт включается конфигурацией; при отключении учёт лимитов не влияет на запуск задач.

## Обоснование

Учёт и упреждающая блокировка не дают исчерпать бюджет и получить жёсткие отказы, а также делают расход ресурсов наблюдаемым и управляемым.
