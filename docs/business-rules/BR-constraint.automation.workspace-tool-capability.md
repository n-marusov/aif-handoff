# BR-constraint.automation.workspace-tool-capability — Полнота операций workspace tools

> Набор workspace tools, предоставляемый implementer-субагенту, должен покрывать все файловые операции, необходимые для выполнения плана задачи: чтение, создание и модификация файлов.

## Правило

Workspace tools, доступные субагенту-реализатору (implementer), в совокупности должны поддерживать все базовые файловые операции, необходимые для исполнения утверждённого плана задачи: создание новых файлов, чтение существующих файлов и модификацию существующих файлов. Ни один план не должен требовать файловой операции, для которой нет соответствующего workspace tool.

## Детализация

- **Чтение** — `read_file` для существующих файлов.
- **Создание** — `write_file` для файлов, которых ещё нет в рабочей директории. Инструмент автоматически создаёт родительские директории.
- **Модификация** — `apply_patch` для замены уникального текстового фрагмента в существующем файле.
- **Shell-команды** — `shell_exec` для выполнения shell-команд в worktree задачи (включая git, тесты, линтеры). Инструмент проверяет команды по денайл-списку опасных операций.
- **Перезапись** — `write_file` также может перезаписывать существующие файлы, но приоритетным инструментом для точечных изменений является `apply_patch` (с бекапом в `.llm-backup/`).
- **Отсутствие `delete`/`rename`/`move`** — на текущем этапе развития системы не является нарушением: планы задач не должны предусматривать удаление или переименование файлов без предварительного расширения набора инструментов.

## Обоснование

План задачи (Change Plan) генерируется AI и может включать создание новых артефактов (файлов конфигурации, документации, тестов, модулей). Если для операции создания нет инструмента, субагент вынужден использовать `apply_patch` с пустым `oldText`, что ведёт к ошибкам валидации и потере контекста задачи. Полнота набора инструментов — необходимое условие для безостановочного выполнения планов.
