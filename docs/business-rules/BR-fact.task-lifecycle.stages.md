# BR-fact.task-lifecycle.stages — Стадии жизненного цикла задачи

> Задача последовательно проходит фиксированный набор стадий от регистрации до приёмки; каждая стадия имеет одно назначение.

## Правило

Задача в любой момент находится ровно в одной стадии из фиксированного набора. Набор стадий и их назначение не зависят от реализации и определяют терминологию продукта.

| Стадия             | Назначение                                                         |
| ------------------ | ------------------------------------------------------------------ |
| Backlog            | Исходное состояние. Задача зарегистрирована, но не взята в работу. |
| Planning           | Разработка плана реализации.                                       |
| Improve            | Доработка плана по результатам ревью или репланирования.           |
| Plan Review        | План готов, ожидает разрешения на реализацию.                      |
| Implementing       | Выполнение работ по задаче.                                        |
| Verify             | Проверка результата на соответствие критериям качества.            |
| Review             | Ревью результата.                                                  |
| Blocked (External) | Выполнение приостановлено из-за внешней зависимости.               |
| Done               | Работы завершены, результат доступен для приёмки.                  |
| Accepted           | Задача принята заказчиком. Финальное состояние.                    |

## Детализация

- Стадии `Verify` и `Review` упорядочены: проверка предшествует ревью.
- `Blocked (External)` — не этап продвижения, а состояние приостановки; оно может быть установлено с любой стадии.
- `Accepted` — единственное неизменяемое финальное состояние; `Done` — терминальное для автоматизации, но обратимое решением человека.
- `Plan Review` — единая точка входа в реализацию после планирования. Разрешение на реализацию даётся утверждением человека (`approve_plan`) либо автоматически (`autoMode`).

## Обоснование

Единый набор стадий обеспечивает сопоставимость статусов между проектами, предсказуемость конвейера и однозначную трассируемость перехода требований в результат.
