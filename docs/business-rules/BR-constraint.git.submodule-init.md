# BR-constraint.git.submodule-init — Инициализация субмодулей при подготовке репозитория

> При подготовке локального репозитория (git-prepare) автоматически инициализируются все субмодули, определённые в `.gitmodules`.

## Правило

Локальный репозиторий проекта после git-prepare должен содержать полную рабочую копию: если в корне проекта присутствует файл `.gitmodules`, все субмодули должны быть инициализированы и извлечены (`git submodule update --init --recursive`) до выполнения любых операций, требующих целостности дерева.

## Детализация

- Инициализация субмодулей выполняется после fetch и checkout дефолтной ветки.
- Выполняется только при наличии `.gitmodules` — отсутствие файла не считается ошибкой.
- Ошибка инициализации субмодуля (недоступность remote URL субмодуля, ошибка аутентификации) блокирует prepare и возвращает ошибку `submodule_failed`.
- Инициализация рекурсивная (`--recursive`) — покрывает вложенные субмодули.

## Обоснование

Проекты с субмодулями (например, общие библиотеки, монорепозитории с внешними зависимостями) требуют полного извлечения субмодулей для корректной работы AI-субагентов: импорта задач, анализа кода, генерации планов и коммитов. Без инициализации субмодулей рабочее дерево неполно, что приводит к ошибкам при чтении кода и выполнении git-операций.
