# BR-constraint.project.scaffold-idempotency — Идемпотентность инициализации AI Factory scaffold

> AI Factory scaffold (директория `.ai-factory/`) инициализируется только при отсутствии; повторный запуск git-prepare не перезаписывает существующий scaffold.

## Правило

При автоматической подготовке репозитория (git-prepare) AI Factory scaffold инициализируется только в том случае, если в проекте отсутствует директория `.ai-factory/`. Наличие существующего scaffold не является ошибкой — инициализация пропускается, prepare продолжается без изменений.

## Детализация

- Проверка наличия `.ai-factory/` выполняется после checkout дефолтной ветки и инициализации субмодулей.
- Если `.ai-factory/` существует — шаг инициализации пропускается (idempotent).
- Если `.ai-factory/` отсутствует — выполняется полная инициализация scaffold через `initProject`.
- Ошибка инициализации (отсутствие registry, неудачная запись файлов) блокирует prepare и возвращает ошибку `init_failed`.
- Повторный вызов git-prepare (например, повторное Sync now) не запускает prepare, так как `gitPreparedAt` уже установлен — scaffold остаётся в текущем состоянии без изменений.
- Правило действует для обоих провайдеров (GitHub, GitLab), так как оба используют общий `prepareRepository`.

## Обоснование

1. **Идемпотентность:** Пользователь может подключить уже существующий проект AI Factory. Scaffold должен быть создан однократно; повторная инициализация не должна перезаписывать существующие файлы конфигурации.
2. **Сохранность конфигурации:** Проект может содержать кастомизированные файлы `.ai-factory/` (конфигурация, кастомные скиллы, правила), которые не должны быть перезаписаны автоматически.
3. **Производительность:** Инициализация scaffold включает создание файлов и запись в репозиторий. Пропуск шага при наличии scaffold сокращает время prepare.
