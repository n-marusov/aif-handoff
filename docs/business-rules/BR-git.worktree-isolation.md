# BR-git.worktree-isolation — Изоляция рабочего дерева задачи

> Каждая задача выполняется в изоляции; рабочее дерево задачи определяется ветвью, база данных — источник истины, а незафиксированная работа не уничтожается при очистке.

## Правило

Задача выполняется в изолированном рабочем дереве, привязанном к её ветке. Путь рабочего дерева — детерминированная функция ветки, а не идентификатора задачи. Состояние рабочих деревьев сверяется с базой данных как источником истины.

## Детализация

- Путь рабочего дерева не зависит от идентификатора задачи; имя ветки, зафиксированное при первой публикации, определяет путь.
- Сверка БД ↔ диск удаляет рабочие деревья, не связанные ни с одной живой задачей; рабочее дерево живой ветки не удаляется.
- Нездоровые регистрации (отсутствующая папка, нарушенная связь `.git`) принудительно удаляются и вычищаются, чтобы не удерживать ветку.
- Перед удалением рабочего дерева незафиксированная работа сохраняется (stash), а не уничтожается; при неудаче сохранения удаление не выполняется.
- Удаление пропускается, если на то же рабочее дерево ссылается другая живая задача; сама ветка сохраняется, так как может понадобиться открытому PR/MR.
- Отсутствующее рабочее дерево живой задачи пересоздаётся по каноническому пути; при невозможности пересоздания задача фиксируется как `Blocked (External)` с сохранением прежней стадии.
- Работа, вышедшая за пределы задачи, фиксируется как предупреждение, а не коммитится молча.
- Базовая ветка для создания worktree разрешается по цепочке fallback:
  `config.base_branch → origin/HEAD → "master" → getCurrentBranch() (HEAD)`.
  Если `configuredBase = "main"` отсутствует, система последовательно проверяет
  `origin/HEAD`, локальную `master` и текущую HEAD. Это гарантирует работу с
  репозиториями, использующими нестандартное имя главной ветки ("master", "trunk",
  "develop" и т.д.), а также с пустыми репозиториями ("No commits yet"), где
  `git show-ref` не находит ref ветки, но HEAD на неё указывает.
- Подключение и синхронизация внешнего VCS-репозитория (GitHub/GitLab) автоматически
  клонирует/инициализирует локальный репозиторий: добавляет `origin`, настраивает
  credential helper, устанавливает `safe.directory`, выполняет fetch и checkout дефолтной
  ветки, а также инициализирует AI Factory scaffold при его отсутствии.

## Обоснование

Изоляция рабочих копий позволяет выполнять задачи параллельно без конфликтов, а сверка с БД и сохранение незафиксированной работы защищают от потери изменений и «зависших» ресурсов.
