# BR-inference.git.review-decision-precedence — Действующее решение ревью

> Разрешением на продолжение работы служит только действующее решение ревьюера — последнее по времени и не отозванное; каждое решение применяется не более одного раза.

## Правило

Действующим решением ревьюера по PR/MR считается его последнее по времени решение, которое не было отозвано. Только действующее решение управляет стадией задачи: одобрение открывает гейт плана и/или принимает результат, запрос изменений возвращает задачу на доработку, а отозванное одобрение не даёт разрешения на продолжение работы.

## Детализация

- Решение ревьюера поступает из внешней системы ревью как событие; система применяет его к задаче один раз — повторная сверка уже применённого решения состояние задачи не меняет.
- Одобрением считается решение, подтверждённое фактическим одобряющим. Формальный признак «одобрено», выставляемый внешней системой без одобряющих, одобрением не является.
- Отзыв одобрения отменяет ранее выданное разрешение: явный отзыв и автоматический сброс одобрений при обновлении содержимого ветки равнозначны по последствиям.
- Когда необработанных решений накопилось несколько, действует последнее по времени; более ранние решения не применяются.
- Если решение не удалось применить из-за конкурентного изменения состояния задачи, оно остаётся необработанным и применяется при следующей сверке — решение не теряется.
- Отсутствие одобрения не завершает задачу: гейт ожидает решения ревьюера, пока задача остаётся в соответствующей стадии.

## Обоснование

Ревью — это диалог, а не разовое событие: решение ревьюера может измениться (одобрение отозвано, изменения запрошены, ветка обновлена новыми коммитами). Если система реагирует на исторический факт одобрения, а не на текущее решение, задача уходит в реализацию без действующего согласия человека — гейт теряет смысл. Правило фиксирует, какое из решений является основанием для продолжения работы.
