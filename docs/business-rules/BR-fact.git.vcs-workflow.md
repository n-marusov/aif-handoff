# BR-fact.git.vcs-workflow — Модель работы с внешней VCS

> Внешняя VCS-интеграция следует модели «одна задача — одна ветка — один PR/MR»; синхронизация двунаправленная, а финальная публикация не закрывает issue раньше времени.

## Правило

Внешняя система работ синхронизируется с задачами по модели «одна задача — одна ветка — один PR/MR». Система не заменяет VCS: она проверяет статусы, но не запускает CI/CD и не выполняет слияние.

## Детализация

- Один проект имеет не более одной привязки к репозиторию; одна внешняя задача соответствует одной задаче полного режима.
- В развёртывании активен только один провайдер внешней системы; интеграция включается отдельным признаком и по умолчанию выключена, сохраняя прежнее поведение.
- План публикуется как черновик PR/MR, не закрывающий внешнюю задачу; закрывающее указание добавляется только при финальной публикации, которая обновляет тот же PR/MR.
- Слияние PR/MR переводит задачу в принятое состояние, в том числе когда задача ещё не завершила стадию ревью: решение человека закрывает ревью и принимает результат; закрытие без слияния приостанавливает задачу.
- Реакция на запрос изменений со стороны ревью — по фронту события, чтобы повторные синхронизации не «отбрасывали» задачу назад; действующим считается только последнее неотозванное решение ревьюера ([`BR-inference.git.review-decision-precedence`](BR-inference.git.review-decision-precedence.md)).
- Ошибки доступа, лимитов или отправки изменений выявляются или приводят к приостановке, не создавая вторую задачу или второй PR/MR.
- Токен доступа никогда не встраивается в Git-команды: отправка использует настроенные учётные данные Git, а операции с PR/MR — аутентифицированный внутренний API.
- Текст внешней задачи доступен только для чтения в интерфейсе.

## Обоснование

Модель «одна задача — один PR/MR» обеспечивает атомарность изменения, прослеживаемость и предсказуемую реакцию на решения ревьюеров.
