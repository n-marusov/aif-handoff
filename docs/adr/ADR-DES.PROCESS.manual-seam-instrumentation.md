# ADR-DES.PROCESS.manual-seam-instrumentation

**Статус:** ПРЕДЛОЖЕНО
**Дата:** 2026-09-18
**Контекст:** Телеметрия требует точек съёма. Значительная часть сигналов уже собирается на явных границах: `wrapAdapter()`/`wrappedRun()` в `packages/runtime/src/registry.ts` оборачивает каждый запуск адаптера и передаёт `result.usage` в `RuntimeUsageSink`; `requestLogger` в `packages/api/src/middleware/logger.ts` измеряет длительность HTTP-запросов; `toolEvents.ts` нормализует вызовы инструментов в события `tool:use`; `@aif/data` — единственный путь к базе (lint-guard); `notifier.ts` и `internalApi.ts` — HTTP-границы между `agent` и `api`; `packages/mcp/src/server.ts` — граница MCP. Проект целиком работает в ESM: разработка `node --import tsx src/index.ts`, production `node dist/index.js`.

**Требование-источник:** `ADR-DES.OPS.otel-collector-adoption`, `.ai-factory/ARCHITECTURE.md` (направление зависимостей, публичные API), evidence: `packages/runtime/src/registry.ts`, `packages/runtime/src/usageSink.ts`, `packages/api/src/middleware/logger.ts`, `packages/runtime/src/toolEvents.ts`

**Решение:** Ручная instrumentация на существующих границах модулей; автоинструментация через ESM loader hook не вводится.

Для запусков адаптеров в `@aif/runtime` объявляется **порт телеметрии** (`startRun` → handle с setAttribute/addEvent/end) — только интерфейс и noop-реализация, без зависимости от OTel SDK, по образцу `RuntimeUsageSink`. Реестр вызывает порт в `wrappedRun()` рядом с `recordUsage()`; это даёт жизненный цикл спана (недоступный post-factum `record(event)`), а `runtime` остаётся свободным от OTel. Реализация порта, инициализация SDK и flush — в новом пакете `@aif/telemetry` (Node-экспорт и browser-экспорт по образцу `@aif/shared`). Инициализация вызывается явным первым импортом в точках входа вместо предзагрузки через `--import`/`NODE_OPTIONS` — меньше правок в entrypoint контейнера, предсказуемый порядок при `tsx`-перезапусках. В браузере стек подключается лениво после первого рендера (гейт `npm run ai:perf`). Вызовы SDK провайдера внутри адаптера не декомпозируются: фиксируется логическая операция, как её видит вызывающая сторона.

**Рассмотренные альтернативы:**

- **`auto-instrumentations-node` + `--experimental-loader=@opentelemetry/instrumentation/hook.mjs`.** Отвергнуто для MVP: experimental hook обязателен и в dev, и в prod; документация OTel JS (`doc/esm-support.md`) предупреждает о нестабильности для TypeScript-as-ESM. Точечная автоинструментация отдельных библиотек допустима позже.
- **Instrumentation внутри каждого адаптера.** Отвергнуто: четыре встроенных адаптера плюс внешние модули дублировали бы контракт; правило кросс-адаптерной согласованности превращает любое изменение в синхронную правку всех адаптеров.
- **Post-factum событие вместо жизненного цикла спана** (по образцу `RuntimeUsageSink`). Отвергнуто: нельзя измерить длительность, время до первого ответа, статус ошибки в момент исключения.

**Последствия:**

- **Положительные:** запуск не зависит от experimental-механизмов загрузки модулей; точки съёма совпадают с границами модулей; новый адаптер получает телеметрию автоматически через реестр; `@aif/runtime` остаётся без OTel-зависимости (направление зависимостей соблюдено); stdio-MCP не затрагивается.
- **Отрицательные:** новые границы требуют явного добавления точек съёма; нет покрытия сторонних библиотек (`ws`, better-sqlite3) «из коробки»; детальность внутри адаптера ограничена логической операцией.
- **Смягчение:** внешние HTTP-вызовы накрываются тонкой обёрткой в месте вызова; SQL наблюдается семантически на границе `@aif/data`; `drizzle-orm@0.45.2` не даёт публичного OTel-tracing (экспорт `./tracing` — заглушка без публичных типов); перечень границ и сознательных пробелов ведётся в `docs/telemetry.md`.
