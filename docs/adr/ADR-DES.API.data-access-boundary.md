# ADR-DES.API.data-access-boundary

**Статус:** ПРИНЯТО
**Дата:** 2026-09-14
**Контекст:** Все пакеты проекта нуждаются в доступе к данным: API — для обслуживания запросов, агент — для чтения/записи задач и метаданных, MCP — для инструментов синхронизации. Без централизованного слоя каждый потребитель писал бы свои SQL-запросы, дублируя логику и создавая риск расхождения схем.

**Требование-источник:** `vision.md` §2.1 (функциональные блоки), `.ai-factory/ARCHITECTURE.md`, `docs/architecture.md` §Packages

**Решение:** Все операции с SQLite выполняются исключительно через централизованный пакет `@aif/data`. Каждый репозиторий (файл) в `packages/data/src/` — одна ответственность: `participants.ts` (жизненный цикл участников), `authSessions.ts` (сессии/CSRF), `taskOwnership.ts` (handoff/назначения), `taskTransitions.ts` (переходы статусов с аудитом), `audit.ts` (immutable аудит). Пакет `shared` остаётся единственным местом определения схемы (drizzle-orm). Прямые импорты DB-хелперов из `@aif/shared` и SQL-конструкции из других пакетов заблокированы ESLint-правилом.

**Рассмотренные альтернативы:**

- **SQL-запросы в каждом пакете** — каждый пакет пишет свои запросы. Отвергнуто: дублирование, расхождение схем, нарушение DRY.
- **DAO-level helpers в shared** — helper-функции в `@aif/shared`, вызываемые из любого пакета. Отвергнуто: размывание границы shared (он должен оставаться pure foundation, см. ADR-DES.STACK.modular-monolith-adoption) и усложнение browser-safe экспорта.
- **ORM в каждом пакете** — каждый пакет импортирует drizzle и schema напрямую. Отвергнуто: ESLint-правило `no-restricted-imports` должно быть единственной точкой контроля; `web` не должен знать о drizzle.

**Последствия:**

- **Положительные:** единая точка истины для SQL; все транзакционные паттерны (handoff, transition, audit) сконцентрированы в одном месте; ESLint-правило делает границу enforce-able.
- **Отрицательные:** любой новый запрос к БД требует добавления функции в `@aif/data` — дополнительный шаг в разработке; операции, требующие обхода слоя (например, миграции), всё ещё проходят через shared.
- **Смягчение:** миграции остаются в `packages/data/src/db.ts` (драйвер перенесён в @aif/data при clean-architecture рефакторинге) как часть контракта схемы, не нарушая границу. Для новых запросов — добавление функции в соответствующий data-файл.
