# ADR-IMPL.DATA.sqlite-drizzle-adoption

**Статус:** ПРИНЯТО
**Дата:** 2026-09-14
**Контекст:** AIF Handoff — однопроцессная система (Modular Monolith), работающая локально или на одном сервере. Данные (задачи, проекты, профили рантаймов, чат) структурированы, но объём невелик — десятки-сотни задач, без распределённой нагрузки. Для такого профиля полноценная клиент-серверная СУБД (PostgreSQL) избыточна.

**Требование-источник:** `vision.md` §2.1 (функциональные блоки), `docs/architecture.md` §Database

**Решение:** SQLite через `better-sqlite3` (синхронный, нативный) с `drizzle-orm` (type-safe, schema-first). Схема — в `packages/shared/src/schema.ts`, все миграции — в `packages/shared/src/db.ts`. Drizzle обеспечивает TypeScript-типизацию запросов без генерации кода (no `prisma generate`), что упрощает CI/CD. `better-sqlite3` выбран за синхронный API (не нужно await для локальных вызовов, проще контроль транзакций) и нативную производительность (C binding). Ключевые таблицы: tasks, projects, runtime_profiles, chat_sessions, chat_messages, participants, task_comments, github/gitlab репозитории и issues, codex_sessions и limit metadata.

**Рассмотренные альтернативы:**

- **PostgreSQL** — полноценная клиент-серверная СУБД. Отвергнуто: операционная сложность (установка, настройка, бэкапы) не оправдана для однопроцессного сценария; внешняя зависимость усложняет развёртывание.
- **Prisma + PostgreSQL** — ORM с генератором и миграциями. Отвергнуто: Prisma генерирует клиент, что добавляет шаг в сборку; `drizzle-orm` читает схему напрямую, типы — в runtime из схемы.
- **better-sqlite3 без ORM** — сырые SQL-запросы. Отвергнуто: отсутствие type-safe запросов, ручное поддержание соответствия схемы и типов.
- **sql.js (WebAssembly)** — альтернативный SQLite драйвер. Отвергнуто: медленнее `better-sqlite3` (интерпретация vs нативный), не подходит для Node.js.

**Последствия:**

- **Положительные:** zero-деплой (файл `.sqlite`, не нужен отдельный сервер БД); синхронные транзакции упрощают atomic-операции (handoff, перехода статусов); Drizzle — лёгкий, без генерации кода; type-safe миграции.
- **Отрицательные:** нет архитектуры «master-replica»; нет built-in репликации; с ростом данных (сотни тысяч задач) SQLite может стать узким горлом; все ворктеры используют одну БД (писатель блокирует читателей).
- **Смягчение:** WAL-режим (`PRAGMA journal_mode=WAL`) для конкурентных чтений; `busy_timeout` для записи; индексы (см. docs/architecture.md §Indexes) для часто используемых запросов. Если проект вырастет — миграция на PostgreSQL через замену драйвера и drizzle-диалекта.
