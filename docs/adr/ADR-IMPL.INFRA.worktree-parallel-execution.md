# ADR-IMPL.INFRA.worktree-parallel-execution

**Статус:** ПРИНЯТО
**Дата:** 2026-09-14
**Контекст:** При работе нескольких задач параллельно в одном проекте каждая требует собственной git-ветки и изолированной рабочей директории. Без изоляции одновременные коммиты/пуш из разных задач в одной директории создают race condition — stash/rebase/push одного процесса ломает дерево другого. При этом каждая задача должна иметь возможность коммитить и пушить изменения независимо, а удаление выполненной задачи не должно затрагивать другие.

**Требование-источник:** `docs/architecture.md` §Worktree Lifecycle, `vision.md` §1.4 HF-5

**Решение:** Каждая задача, запущенная в parallel-проекте с `AIF_TASK_WORKTREES_ENABLED=true`, получает изолированный git worktree: `git worktree add <worktreePath> <branch>`. Путь работы (worktree) сохраняется в `tasks.worktree_path`. Координатор запускает все стадии (planning → implementing → review → done) из этого worktree. Контроль:

- **Single writer:** каждая task-ветка привязана к одному worktree; мьютекс `gitOperationLock` блокирует одновременные git-операции в рамках одного проекта.
- **Worktree identity:** worktree идентифицируется по `tasks.worktree_path`; при рестарте координатор переиспользует существующий worktree по пути.
- **Lifecycle:** worktree создаётся при переходе на `implementing` (для задач с `plan_review` — после утверждения плана). Удаляется, когда PR/MR задачи слит (`verified`) или задача удалена. Если другая задача использует тот же worktree — удаление пропускается.
- **Stash-before-remove:** несохранённая работа stashe'ится перед удалением worktree, чтобы не потерять изменения.
- **Reconciliation:** `worktreeReconcile.ts` — проверка всех зарегистрированных worktree при каждом poll cycle: удаляет осиротевшие записи в БД, чинит расхождения, удаляет мёртвые директории.

**Рассмотренные альтернативы:**

- **Единая рабочая директория с branch switching** — переключение веток в одной директории. Отвергнуто: race condition при одновременном запуске задач, потеря stashe'й, конфликты rebase при автоматическом пуше.
- **Копирование директории (cp -r)** — полная копия репозитория на каждую задачу. Отвергнуто: дублирование истории git (гигабайты), медленное создание, проблема синхронизации с origin.
- **No isolation — serial execution only** — только последовательное выполнение задач. Отвергнуто: не масштабируется; парадигма auto-queue требует параллельного наполнения пула задач.

**Последствия:**

- **Положительные:** полная изоляция git-операций; каждая задача коммитит/пушит независимо; удаление задачи не затрагивает другие; параллельные проекты могут иметь несколько задач в разных стадиях.
- **Отрицательные:** создание worktree — затратная операция (re-create object store); при большом количестве worktree (10+) диск растёт; сложная логика cleanup (stash, reconcile).
- **Смягчение:** при `AIF_TASK_WORKTREES_ENABLED=false` — fallback к shared branch с serial execution; лимит параллельных задач на проект (`COORDINATOR_MAX_CONCURRENT_TASKS_PER_PROJECT`, default 3); reconcile-сборка мусора каждый poll cycle.
