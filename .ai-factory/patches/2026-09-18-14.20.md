# Container diagram dropped three personas that the context diagram declares

**Date:** 2026-09-18 14:20
**Files:** docs/c4/container.md
**Severity:** low

## Problem

`docs/c4/container.md` declared only two human personas (`Developer`, `Администратор`),
while `docs/c4/context.md` declared five (`Developer`, `Технический лид`, `Product Owner`,
`QA-инженер`, `Администратор`). The same system therefore showed two different actor sets
at C4 levels 1 and 2 — a reader of the container diagram alone would not see the tech lead,
product owner, or QA engineer as users at all, even though their functions (runtime profiles
and limits, business rules and escalations, test gates) are container-level features served by
`web` → `api`.

## Root Cause

The container document was written bottom-up from the deployment artifacts
(`docker-compose*.yml`, `.docker/Dockerfile`) and the `packages/` layout, so its actor list
was derived from the personas that happened to appear in its own "Ключевые сценарии (кратко)"
section (task creation, administration, MCP). Level 1 was authored independently from
`vision.md` §3.1 and therefore kept the full persona set. Nothing tied the two documents
together: there was no requirement in `docs/c4/README.md`'s "Формат описания" that the
container diagram re-declare the personas of the level above, and no check that compared them.

## Solution

- Added the three missing `Person(...)` entries to the `C4Container` diagram in the same order
  and with the same ids as `context.md` (`techlead`, `po`, `qa`), so the diagrams can be
  diffed by identifier.
- Added one `Rel(<persona>, web, ...)` per new persona (HTTPS), reflecting that every human
  persona reaches this system through the `web` container only, and normalized `admin`'s
  description from a noun list to the verb phrase used by its siblings.
- Added a leading "Контекст" bullet stating the modeling decision explicitly: the five human
  personas are the only external actors, they differ by role and permissions rather than by
  channel, the set matches level 1, and AI agents stay internal (launched by `agent`).
- Verified parity programmatically by extracting `Person(<id>` matches from both files
  (`admin, developer, po, qa, techlead` — 5 and 5) and by running
  `npx prettier --check docs/c4/*.md`.

## Prevention

- Treat the C4 levels as a chain: when a persona set changes at one level, enumerate the other
  level files under `docs/c4/` and reconcile the actor declarations in the same change.
- Prefer identical `Person` ids and ordering across levels so parity can be checked with a
  simple extraction instead of a visual review.
- A cheap regression guard is a test that reads `docs/c4/context.md` and `docs/c4/container.md`
  and asserts both declare the same set of `Person(<id>` identifiers — the class of drift is
  exactly "same system, different actor list", which a set comparison catches completely.
- `docs/c4/README.md`'s "Формат описания" enumerates what each diagram file must contain; if
  persona parity is meant to be mandatory, it belongs there as an explicit rule.
