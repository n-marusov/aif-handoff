# Fix pre-existing tsc baseline errors across packages (0-error build)

**Date:** 2026-09-19
**Files:**
- `packages/data/src/tasks.ts` (3× `resolveTaskPermissions` views)
- `packages/data/src/__tests__/splitContract.contract.test.ts`
- `packages/runtime/src/resolution.ts`
- `packages/runtime/src/__tests__/adapterDescriptor.contract.test.ts`
**Severity:** medium

## Problem

`npm run build` (tsc across all packages) failed on 7 pre-existing type errors that
blocked the build/CI baseline to zero:

1. `packages/data/src/tasks.ts` — 3× TS2345: `resolveTaskPermissions` view objects
   (`toTaskResponse`, `toTaskListItem`, `toTaskSummary`) lacked the required `id`
   field of `TaskPolicyView`.
2. `packages/data/src/__tests__/splitContract.contract.test.ts` — 3× TS2345:
   `makeLimitSnapshot()` returned `Record<string, unknown>` (spread not assignable
   to `RuntimeLimitSnapshot`), and `id` (`string | null` from `seedGatedProfile`)
   passed to `findRuntimeProfileById(id)`.
3. `packages/runtime/src/resolution.ts` — TS2345: `resolveApiKey(defaultApiKeyEnvVar, env)`
   passed `string | null` to a `string` parameter.
4. `packages/runtime/src/__tests__/adapterDescriptor.contract.test.ts` — 9× TS18048:
   property access on optional descriptor fields `apiKeyEnvCandidates` / `effort`.

## Root Cause

1. `TaskPolicyView` (in `shared/stateMachine.ts`) requires `id`, but the three
   presenter views built at the data boundary omitted it. `resolveTaskPermissions`
   uses `id` only for logging (`logTransitionDecision`), never for the permission
   outcome — so the fix is statically required, behaviorally neutral.
2. The test helper returned a deliberately loose `Record<string, unknown>` to avoid
   importing the type — the typo-style laziness caused the spread to lose its
   assignability. The `!` was placed on `findRuntimeProfileById(...)` instead of on
   the nullable `id` argument.
3. `inferDefaultApiKeyEnvVar` returns `string | null`, and the fallback branch could
   be entered when `defaultApiKeyEnvVar === null` (explicit-but-empty profile env var
   with no inference). At runtime `resolveApiKey(null)` read `env["null"]` and
   returned null — behaviorally harmless but semantically wrong and type-unsafe.
4. The descriptor contract test (Task 9 red-phase) reads contract fields that are
   optional in `RuntimeDescriptor`; `modelDiscovery.test.ts` / `registry.test.ts`
   mocks intentionally omit them, so making the fields required would break dozens of
   mocks. The test itself exists to pin the built-in adapters' declarations.

## Solution

1. Added `id: task.id` / `id: row.id` to the three `resolveTaskPermissions` view
   objects in `tasks.ts` (behavior-neutral: `id` feeds only the transition log).
2. Typed `makeLimitSnapshot(): RuntimeLimitSnapshot` (imported the type) and moved
   the null-assertion to the argument: `findRuntimeProfileById(id!)`. The mock fully
   satisfies the snapshot shape, and the assertion expresses the seeded-profile
   invariant at the call site.
3. Added `defaultApiKeyEnvVar &&` to the fallback-branch condition in
   `resolution.ts` — when the default is null there is no canonical fallback to try,
   and the branch becomes unreachable (identical runtime outcome, now type-safe).
4. Added `!` non-null assertions at the descriptor contract test's property accesses
   (`d.opencode.apiKeyEnvCandidates!.length`, `d.*.effort!.optionKey`,
   `d.*.effort!.fallbackLevels`) — the test's purpose is to pin that built-in
   adapters declare the contract, while the descriptor type stays optional for
   minimal third-party and test mocks.

## Prevention

- Presenter views built against a `Pick<Task, ...>` contract must include all
  required keys the contract demands — TS structural assignability is the safety net.
- Test helpers that fabricate persisted JSON should be typed as the target contract
  type (e.g. `RuntimeLimitSnapshot`), not as `Record<string, unknown>`, so spreads
  keep their assignability.
- Non-null assertions belong on the nullable INGREDIENT (`id!`), not on the outer
  call — assert the unsafe value, not its consumer.
- When an `env` resolver returns `string | null` and a branch semantics require
  non-null, add the null guard to the condition rather than relying on runtime
  `env[null]` fallback behavior.
- After every refactor, run `npx tsc --noEmit -p packages/*/tsconfig.json` across
  ALL packages — the package-local build script alone misses cross-package surface.
