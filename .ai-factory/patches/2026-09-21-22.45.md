## Problem

1. GitLab shortcut import always created tasks as `executionOwner="ai"`, `autoMode=true`,
   ignoring the project's `autoQueueMode` — a contract mismatch that made the GUI L-10
   e2e fail (expected `human`, got `ai`).
2. LLM-dependent e2e tests failed (`fail`) instead of skipping when `AIF_LLM_INTEGRATION`
   was disabled, polluting the deterministic CI signal.
3. `createGitLabBranchWithCommit` returned HTTP 400 on already-existing branches (race),
   without surfaceable diagnostics.
4. Planner e2e scenarios flaked into `blocked_external` due to `?? .ai-factory/plans/`
   dirty worktree in test roots.
5. The GitLab US was overloaded (24 scenarios in one file) with blurred API/GUI oracle
   boundaries and duplicated assertions.

## Root Cause

- **Contract mismatch:** the data-layer import didn't branch on project state that
  already existed in the DB (`projects.autoQueueMode`); the ownership model
  (`executionOwner`/`autoMode`) was designed later than the GitLab import path.
- **LLM lane:** capability preconditions were written as hard asserts inside tests
  rather than as conditional applicability; the suite had no core/llm lane split.
- **Branch helper:** no pre-check; POST create is not idempotent in GitLab CE; raw 400
  bodies were swallowed by the generic error type.
- **Worktree hygiene:** e2e provisioning never cleaned service artifacts under
  `/home/www/*` before running planner scenarios.
- **Overloaded US/tests:** one US file accumulated the whole lifecycle; the oracle-layer
  policy was implicit.

## Solution

- `importGitLabIssueTask` now derives owner + autoMode from `project.autoQueueMode`
  (true→ai/true, false→human/false) and writes it consistently to task,
  `taskExecutorHistory`, and audit snapshot. E2E updated: LLM lanes enable auto-queue
  before import; API L-10c asserts the human-owned default.
- Added lane split `e2e:core` / `e2e:llm` (npm targets + Makefile + docker mode), a
  fail-fast preflight script, `@requires-llm` tags, and `ensureLlmRuntime` skip logic.
- Hardened `createGitLabBranchWithCommit`: pre-check GET, idempotent reuse, structured
  400 payload (`branch`/`ref`), post-create read verification, effective-name return.
- Added `cleanE2eTestRoots()` to e2e provisioning (removes `.ai-factory/` in test roots,
  explicit cleanliness report).
- Decomposed the US into 3 focused stories (shortcut-accept, plan-review, pipeline-run)
  with backward-compatible anchors; created trace matrix + refactor-plan docs; synced
  known-issues statuses.

## Prevention

- Any new import path from VCS must consult project-level ownership flags at write time
  and keep task/executor-history/audit snapshots consistent (test both branches).
- LLM-dependent e2e must use lane tags + skip semantics, not hard asserts; keep the
  fail-fast preflight in front of the llm lane.
- Test helpers that mutate external state must be idempotent, self-verifying, and
  surface structured errors (branch/ref).
- The oracle-layer policy (API = state machine; GUI = UX) must be documented per test
  and per US; duplicate pairs get explicit primary/secondary markings.
- Keep US decomposition criteria: one story = one user-visible outcome family;
  preserve anchors for backward compatibility.
