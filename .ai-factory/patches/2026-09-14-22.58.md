# Docker build failure in @aif/agent — two TypeScript compilation errors

**Date:** 2026-09-14 22:58
**Files:** packages/agent/src/gitlabPrepare.ts, packages/agent/src/__tests__/internalApi.test.ts
**Severity:** high

## Problem

`make docker-build` failed at the `@aif/agent` build stage with two TypeScript errors:

1. `src/gitlabPrepare.ts(14,15): error TS2552` — `RepositoryPrepareErrorKind` not found
2. `src/__tests__/internalApi.test.ts(75,13): error TS2554` — `GitLabPrepareError` constructor expected 4 arguments, got 3

## Root Cause

Both errors stemmed from the same refactoring: the `RepositoryPrepareError` class in `repositoryPrepare.ts` was extended to include a 4th mandatory parameter `provider: RepositoryProvider`, and the `RepositoryPrepareErrorKind` type was introduced alongside it.

- **Error 1:** `gitlabPrepare.ts` re-exports `RepositoryPrepareErrorKind as GitLabPrepareErrorKind` but never imported it — only `prepareRepository` and `RepositoryPrepareError` were imported from `repositoryPrepare.js`. The re-export line was added without the corresponding import.
- **Error 2:** The test `internalApi.test.ts` constructed `GitLabPrepareError` (which is `RepositoryPrepareError` re-exported) with only 3 arguments (`kind`, `message`, `projectId`) — missing the 4th `provider` parameter that was added to the constructor.

## Solution

- **gitlabPrepare.ts:** Added `RepositoryPrepareErrorKind` to the import from `./repositoryPrepare.js`
- **internalApi.test.ts:** Added `"gitlab"` as the 4th argument to the `GitLabPrepareError` constructor call

## Prevention

- When extending a shared class constructor with new mandatory parameters, grep for all instantiation sites across the codebase (including test files)
- When adding re-export statements that reference a type, verify that type is actually imported first
- Consider running `npx turbo build` after type-definition changes to catch compilation errors before committing
