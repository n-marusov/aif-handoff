# Implementer produced no work-tree changes but task advanced to Done

**Date:** 2026-09-11 12:15
**Files:** `packages/agent/src/subagents/implementer.ts`
**Severity:** high

## Problem

A task whose plan required creating `hello.md` was marked Done, but the file
never appeared in the repository or the PR. The auto-review gate accepted the
result (no blocking findings) even though the diff was empty.

The final PR comment showed boilerplate review text ("Auto Review Metadata",
"Проверю изменения в текущей ветке (diff)") instead of concrete change
information, so nothing signaled that the implementation produced no files.

## Root Cause

Two compounding issues:

1. **Boilerplate-only PR comment.** The PR body includes `implementationLog`,
   but `implementationLog` was just the model's prose output. When the model
   claimed success without creating files, the log said "implemented" with no
   concrete file list, and the reviewer found an empty diff — so the auto-gate
   passed silently.

2. **Plan declared-file parser only understands English.** `parseTaskChangeScope`
   in `planLayers.ts` matches `- Create: <path>` / `- Modify: <path>` style
   bullets only (English keywords). A Russian plan such as "Создать файл:
   hello.md" produces `changeScope.declared = false` and an empty
   `collectDeclaredFiles()` result, so the existing declared-vs-actual scope
   validation had nothing to compare.

## Solution

In `implementer.ts`, after the subagent run and checklist sync:

- Merge tracked changes (`git diff --name-only <baseline>`) and all dirty
  files (`git status --porcelain`, which includes untracked new files) into a
  single `changedFiles` list.
- When `changedFiles.length > 0`, append a `[files]` section listing exactly
  which files the implementation touched. This lands in `implementationLog`,
  which is included in the PR body.
- When the plan had pending tasks but `changedFiles.length === 0`, append a
  loud `[error]` note to `implementationLog` and log an error. Same for
  declared files from `collectDeclaredFiles` that were never modified
  (`[warning]`).

## Prevention

- Any task that reaches Done must carry concrete file evidence in the PR
  comment. If `changedFiles.length === 0` while pending plan tasks exist, the
  pipeline should treat it as a failure signal and surface it to the human.
- `collectDeclaredFiles` should be extended to recognize non-English file
  declaration bullet forms (e.g. "Создать файл:"), so scope validation works
  for localized plans.
