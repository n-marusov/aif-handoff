# Auto-queue commit gate blocked by interactive aif-commit skill

**Date:** 2026-09-11 12:15
**Files:** `packages/agent/src/autoQueueCommit.ts`, `packages/agent/src/__tests__/autoQueueCommit.test.ts`
**Severity:** high

## Problem

The auto-queue commit gate (`ensureAutoQueueTaskCommit`) blocked tasks at the
implementing stage. After the implementer created files, the commit gate ran
the `/aif-commit` skill as a fallback slash command. The skill is interactive
(asks for user confirmation before committing), so in automated context the
subagent completed without executing `git commit`. The gate then detected the
tree was still dirty and threw `StageManualBlockError`, moving the task to
`blocked_external`.

## Root Cause

In `autoQueueCommit.ts`, the workflow spec was created with
`fallbackSlashCommand: "/aif-commit"`:

```typescript
const workflowSpec = createRuntimeWorkflowSpec({
  workflowKind: "commit",
  prompt,
  fallbackSlashCommand: "/aif-commit",
  ...
});
```

This caused `promptPolicy.ts` to set `useSlashFallback = true`, prepending
`/aif-commit\n\n` to the workflow prompt. The `/aif-commit` skill's
instructions (SKILL.md) tell the model to ask for user confirmation
(`AskUserQuestion`) before executing `git commit`. In the automated subagent
context, there is no user to respond — the subagent completes without
committing.

The `buildCommitPrompt(false)` function already produces a complete,
non-interactive prompt telling the model to:
1. Run `git status`
2. Stage ALL changes: `git add -A`
3. Draft a conventional commit message
4. Create the commit: `git commit -m ...`
5. Do NOT push

## Solution

Removed `fallbackSlashCommand: "/aif-commit"` from both the
`createRuntimeWorkflowSpec` and `executeSubagentQuery` calls in
`autoQueueCommit.ts`. Without it, the fallback strategy defaults to `"none"`
and the non-interactive `buildCommitPrompt` output is used directly.

Also updated the test assertion to stop expecting `fallbackSlashCommand`.

## Prevention

- Workflow prompts for automated operations (`buildCommitPrompt`) must be
  self-contained and non-interactive — they should never depend on user
  confirmation.
- When a `fallbackSlashCommand` is provided, verify the target skill can
  operate without user interaction (no `AskUserQuestion`).
- For future automated Git workflows, prefer inline bash commands in the
  prompt over delegated interactive skills.
