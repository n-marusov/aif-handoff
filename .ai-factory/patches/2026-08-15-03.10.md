# 403 feature_disabled on GitLab routes when both provider routers are mounted

**Date:** 2026-08-15 03:10
**Files:** `packages/api/src/routes/github.ts`, `packages/api/src/routes/gitlab.ts`, `packages/api/src/__tests__/gitlab.test.ts`
**Severity:** high

## Problem

`PUT /api/projects/:id/gitlab` (via the Web UI or curl) returned
`403 {"error":"GitHub issue-to-PR mode is disabled","code":"feature_disabled"}`
even though `.env` had `GIT_PROVIDER=gitlab` and `AIF_GITLAB_ISSUE_MR_ENABLED=true`.
The GitLab connect flow was completely blocked in the demo.

## Root Cause

Both provider routers are mounted on the same `/projects` path in
`packages/api/src/index.ts`, in this order:

```
app.route("/projects", projectsRouter);
app.route("/projects", githubRouter);   // mounted FIRST
app.route("/projects", gitlabRouter);   // mounted SECOND
```

Each router had a bare `use("*")` feature-gate middleware. In Hono, `use("*")`
in a sub-router mounted at `/projects` matches **every** `/projects/*` request.
With `GIT_PROVIDER=gitlab`, the GitHub gate's condition
(`GIT_PROVIDER !== "github"` → true) fired and returned 403 **without calling
`next()`**, so the request never reached the GitLab router — regardless of the
GitLab flags.

The existing tests missed this because each test mounted **only one** router
(`app.route("/projects", gitlabRouter)` alone), so the cross-router interception
never happened.

## Solution

Scoped each gate middleware to its own route paths:

- `githubRouter.use("/:id/github", ...)` + `use("/:id/github/*", ...)`
- `gitlabRouter.use("/:id/gitlab", ...)` + `use("/:id/gitlab/*", ...)`

Two patterns are required because Hono's `/:id/gitlab*` wildcard matches
`/gitlab/sync` but **not** the bare `/gitlab` (verified empirically).

Added a regression test that mounts BOTH routers (the real `index.ts` layout)
and asserts GitLab routes pass while GitHub routes still 403 when
`GIT_PROVIDER=gitlab`.

## Prevention

- **When routers share a mount prefix, never gate them with a bare `use("*")`** —
  scope middleware to the provider-specific path segment.
- **Test the real mounting layout**: cross-provider regression tests must mount
  both routers together, not just the one under test.
- Hono path-pattern gotcha: `use("/:id/gitlab*")` does NOT match the bare
  `/gitlab` path — register both `/path` and `/path/*` patterns.
