# Unauthenticated git sync/publish routes (corrected approach)

**Date:** 2026-08-16
**Files:** packages/api/src/middleware/participantAuth.ts, packages/api/src/routes/gitlab.ts, packages/api/src/routes/github.ts, docs/api.md
**Severity:** medium

## Problem

GitLab's `gitlab/sync` and `gitlab/tasks/:taskId/publish` routes were missing from the
trusted-internal path allowlist in `participantAuth.ts` (`isTrustedInternalPath`), while
their GitHub equivalents were already listed. In Participants Mode this meant the agent
could not call them with the internal token, and an initial fix attempt over-corrected by
mounting `internalBroadcastAuth` directly on the routes — which broke the browser
"Sync now" button (it sends no internal token) and the agent in deployments without
`INTERNAL_BROADCAST_TOKEN` configured.

## Root Cause

`internalBroadcastAuth` is the wrong tool for sync: `POST /projects/:id/gitlab/sync` is a
user-facing action (the web UI has a "Sync now" button) AND an agent action. Route-level
`internalBroadcastAuth` rejects every caller without the token, including the browser.
The app's actual auth model is:
- legacy mode (participants off): all `/projects/*` POST routes are open (app-wide model),
- participants mode: `isAdminOnlyRoute` makes non-GET `/projects/*` admin-only, and
  `participantAuth` bypasses participant auth when the internal token matches a
  trusted-internal path.

## Solution

- Reverted the route-level `internalBroadcastAuth` additions (gitlab + github sync/publish).
- Added the GitLab sync/publish paths to `isTrustedInternalPath` in `participantAuth.ts`,
  mirroring the existing GitHub entries, so the agent's internal-token calls pass in
  participants mode.
- Replaced the regression test with one that asserts participants-mode admin protection
  (401 without session/token) and the trusted-internal bypass (not 401 with the token).
- Corrected `docs/api.md` to describe the real model.

## Prevention

- Before enforcing auth on a route, check whether it is user-facing (has a UI button) —
  browser calls must not be gated by an internal-only middleware.
- When mirroring a route pair (GitHub/GitLab), keep the shared auth allowlists symmetric:
  if one provider's path is in `isTrustedInternalPath`, add the other's.
- Verify a security fix against the running deployment's env (NODE_ENV, tokens) — a
  middleware that rejects unconfigured callers will break an open-access deployment.
