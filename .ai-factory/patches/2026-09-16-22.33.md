# Git commit fails with "Author identity unknown" in Docker container

**Date:** 2026-09-16 22:33
**Files:** packages/agent/src/repositoryPrepare.ts
**Severity:** high

## Problem

When connecting a GitLab (or GitHub) repository via the Web UI and clicking
"Sync now", the sync fails with:

```
git commit scaffold failed: Author identity unknown

*** Please tell me who you are.

Run

  git config --global user.email "you@example.com"
  git config --global user.name "Your Name"

fatal: unable to auto-detect email address (got 'node@c31eb0cda310.(none)')
```

The error propagates as `gitlab_prepare_commit_failed` and blocks the import.

## Root Cause

The `prepareRepository` function runs `git commit` (step 9) to commit AI
Factory scaffold files, but neither `user.email` nor `user.name` is configured
in the Docker container's global git config. The container's hostname-based
default (`node@<hostname>.(none)`) is not a valid email address, so git refuses
the commit.

## Solution

Added a new step 8 in `prepareRepository` that configures `user.email` and
`user.name` at the repository level before any commit operation:

```typescript
runGit(projectRoot, ["config", "user.email", "aif-handoff@ai-factory"]);
runGit(projectRoot, ["config", "user.name", "AIF Handoff"]);
```

This is scoped to the repository (not global) so it doesn't affect other
repositories on the same machine. The identity values are generic placeholders
since these commits are only for the AI Factory scaffold, not for user-facing
contributions.

## Prevention

- Any `git commit` in the agent process must be preceded by setting
  `user.email` and `user.name` for the repository, since Docker containers
  have no guaranteed global git identity.
- If additional git commit sites are added to the agent, apply the same local
  config pattern before invoking `git commit`.
