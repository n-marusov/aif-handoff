# MCP container crashes at startup: MCP_AUTH_TOKEN missing for HTTP transport

**Date:** 2026-09-14 23:07
**Files:** docker-compose.yml
**Severity:** medium

## Problem

`docker compose up -d` (make docker-dev) starts all 4 containers, but the MCP container
immediately crashes and enters a restart loop. The API/Web/Agent containers start fine.

Log output:
```
MCP HTTP authentication token is required
MCP_AUTH_TOKEN is required when MCP_TRANSPORT=http.
MCP server failed to start
```

## Root Cause

`docker-compose.yml` sets `MCP_TRANSPORT=http` in the mcp service environment, but does
NOT set `MCP_AUTH_TOKEN`. The `.env` file has `MCP_AUTH_TOKEN` commented out (line 101).
The MCP server code (`packages/mcp/src/env.ts`, line 97-99) requires `authToken` when
transport is `http` — it throws and exits immediately if the token is missing.

This is a configuration gap: all other services with mandatory env vars have either
inline defaults or env-file values, but the MCP HTTP auth token was omitted from both
docker-compose.yml and the active `.env` file.

## Solution

Added `MCP_AUTH_TOKEN=${MCP_AUTH_TOKEN:-charlie-mcp-dev-token}` to the mcp service's
environment block in docker-compose.yml. This follows the same `{VAR:-default}` pattern
used by other services:

- If `MCP_AUTH_TOKEN` is set in the shell environment or `.env` file, it is used
- Otherwise, a safe dev-only default (`charlie-mcp-dev-token`) is applied so the stack
  starts out of the box

## Prevention

- Always cross-reference mandatory config checks in code against the compose file's
  environment block — every field validated in `env.ts` should have a corresponding
  entry in docker-compose.yml or .env
- When adding a new required env var to a container, check all upstream injection points:
  compose environment, env_file, and Makefile defaults
