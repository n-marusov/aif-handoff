# High-severity npm audit advisories in dev dependencies

**Date:** 2026-08-16
**Files:** package-lock.json
**Severity:** medium

## Problem

`npm audit --audit-level=high` reported 8 vulnerabilities (4 moderate, 4 high):
brace-expansion (DoS), js-yaml (quadratic CPU), nanoid (non-secure generator loop),
postcss (source map path traversal), esbuild (dev-server read).

## Root Cause

All advisories were in transitive **dev/build** tooling (Stryker mutation tester,
typescript-eslint, Vite/tsx, drizzle-kit), not in the production runtime path. They
accumulated from long-unrefreshed transitive pins and were surfaced by `npm audit`.

## Solution

Ran `npm audit fix` (non-breaking). It resolved the 4 high-severity issues
(brace-expansion, js-yaml, nanoid, postcss) by updating transitive pins in
package-lock.json. Build (`npm run build`, 7 packages) and tests still pass.

## Prevention

- Run `npm audit` in CI and fail on `--audit-level=high`.
- Schedule `npm audit fix` (non-breaking) alongside dependency bumps; treat the
  remaining `--force`-only esbuild/drizzle-kit advisories as tracked dev-tooling debt
  until a non-breaking upgrade path exists.
- When bumping breaking tooling (e.g. drizzle-kit for esbuild), do it in a dedicated
  PR with its own test run.
