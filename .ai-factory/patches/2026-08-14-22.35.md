# Docker build fails: agent tsc missing AIF_BOOTSTRAP_* env fields in test helper

**Date:** 2026-08-14 22:35
**Files:** `packages/agent/src/__tests__/hooks.test.ts`
**Severity:** medium

## Problem

`docker compose -f docker-compose.production.yml up -d --build` failed at the
shared `npx turbo build` stage:

```
@aif/agent:build: error TS2345: Argument of type '{ ... }' is not assignable
to parameter of type '{ AIF_RUNTIME_MODULES: string[]; ... }'.
  Type '{ ... }' is missing the following properties from type '{ ... }':
  AIF_BOOTSTRAP_RUNTIME_PROFILE_ENABLED, AIF_BOOTSTRAP_RUNTIME_PROFILE_NAME,
  AIF_BOOTSTRAP_RUNTIME_ID, AIF_BOOTSTRAP_PROVIDER_ID, and 4 more.
```

## Root Cause

A new feature added 10 `AIF_BOOTSTRAP_*` **required** fields to the shared
`Env` type (`packages/shared/src/env.ts`). `packages/agent/src/__tests__/hooks.test.ts`
has a local `makeEnv()` helper that hand-builds a full `Env` object literal and
passes it to `mockedGetEnv.mockReturnValue(...)`. The literal was not updated,
so `tsc` (run by `@aif/agent#build` inside the Docker turbo build) rejected it.

The miss was invisible locally because `npm run test`/coverage (vitest) transpiles
without full type-checking; only `tsc` (build) caught it — exactly what the Docker
build runs.

## Solution

Added the 10 new `AIF_BOOTSTRAP_*` fields to `makeEnv()` in
`packages/agent/src/__tests__/hooks.test.ts` with defaults matching the env schema
(flag `false`, name `"Bootstrap (Codex CLI)"`, runtime `codex`, provider `openai`,
transport `cli`, baseUrl/model `undefined`, apiKeyEnvVar `OPENAI_API_KEY`,
setDefaults `true`, forceUpdate `false`).

## Prevention

- **When adding a required field to the shared `Env` type, grep for `makeEnv(` /
  hand-built `Env` literals across ALL packages** (`packages/*/src/__tests__/`) —
  the build fails on any one of them, and the failure surfaces in Docker/turbo
  `build`, not in vitest runs.
- Run `npm run build` (turbo, runs `tsc` in every package) after touching
  `packages/shared/src/env.ts` — vitest transpile does not type-check.
- CI gate `ci: add production docker build gate` catches this; the local
  `docker compose build` is the fastest reproduction.
