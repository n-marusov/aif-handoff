# OpenRouter adapter: detect mid-stream errors, retry 503, check per-choice errors

**Date:** 2026-09-14 20:15
**Files:** packages/runtime/src/adapters/openrouter/api.ts
**Severity:** high

## Problem

Three discrepancies between the OpenRouter adapter implementation and the API spec could silently produce incomplete/truncated output:

1. **Mid-stream SSE errors undetected** — After headers are committed, OpenRouter may deliver a provider failure as an SSE event with `error` and `finish_reason: "error"`. The adapter continued collecting `outputText` and `tool_calls` without checking for error markers. For file generation, this meant a truncated tool call (broken JSON arguments) or partial code output would be returned as a successful result.

2. **503 not retried** — The API spec recommends retrying both 429 and 503. Only 429 was in `RETRYABLE_STATUS`, so a transient 503 caused an immediate failure.

3. **Per-choice errors not checked in non-streaming responses** — A provider can return HTTP 200 with a per-choice `error` object (e.g., content filter hit). The adapter treated this as a success, losing the error signal.

## Root Cause

- The streaming SSE parser in `runOpenRouterStreamingAttempt` parsed `parsed.choices?.[0]?.delta` and `finish_reason` but never inspected `parsed.error`, `parsed.choices?.[0]?.error`, or stopped content accumulation when `finish_reason === "error"`.
- The retry logic `postChatCompletionsWith429Retry` (now `postChatCompletionsWithRetry`) limited retryable status codes to `429`.
- The non-streaming path in `runOpenRouterApi` parsed `payload.choices[0].message` without inspecting `payload.error` or `choice.error`.

## Solution

### Fix 1: SSE mid-stream error detection
In `runOpenRouterStreamingAttempt`, after JSON-parsing each SSE chunk:
- Check `parsed.error` (top-level) and `parsed.choices?.[0]?.error` (per-choice).
- On detection: set `finishReason = "error"`, clear `toolCallSlots`, log with `[FIX]` prefix, and `continue` (skip content accumulation).
- After any error flag, the `finishReason === "error"` guard clears tool call slots and skips content for remaining chunks.
- The stream is drained until `[DONE]`; the final result has `finishReason: "error"`, empty tool calls, and partial `outputText`.

### Fix 2: Add 503 to retryable statuses
- Changed `RETRYABLE_STATUS` from `new Set([429])` to `new Set([429, 503])`.
- Renamed `MAX_429_ATTEMPTS` → `MAX_RETRY_ATTEMPTS`, `postChatCompletionsWith429Retry` → `postChatCompletionsWithRetry`.
- Updated the retry log message from hardcoded "429" to dynamic `${response.status}`.

### Fix 3: Non-streaming per-choice error check
In `runOpenRouterApi`, after parsing the JSON payload:
- Check `payload.error` (top-level): reject with classified error.
- Check `choice.error` (per-choice): log with `[FIX]` prefix, reject with classified error.

All errors use `safeProviderErrorMessage` for redaction and `buildLimitErrorMetadata` for structured metadata.

## Prevention

- SSE parsers should always check for `error` fields in every chunk, not just delta content.
- Retry policies should include both 429 (rate limit) and 503 (server unavailable) for API-only transports.
- Per-choice errors on HTTP 200 must be treated as failures — they carry provider-level error context.
- When adding new adapter tests, include scenarios for mid-stream error events and per-choice errors.
