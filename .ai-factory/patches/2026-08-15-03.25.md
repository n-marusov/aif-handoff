# GitLab connect 400 ZodError: user pasted full URL and token value (UI hardening)

**Date:** 2026-08-15 03:25
**Files:** `packages/web/src/lib/utils.ts`, `packages/web/src/components/project/ProjectSelector.tsx`, `packages/web/src/__tests__/utils.test.ts`
**Severity:** low (UX validation friction)

## Problem

Connecting a GitLab repository from the Web UI returned `400 Bad Request` with
a `ZodError`:

- `repository` `"https://gitlab.com/vedo-ecosystem/vedo-core"` → rejected: must be `namespace/name`.
- `tokenEnvVar` `"glpat-..."` → rejected: must be an uppercase `GITLAB_*` env var name.

The API validation was correct; the user had pasted a full clone URL and the
token **value** into the env-var-name field.

## Root Cause

Two layers of UX gap:

1. The repository field was sent verbatim; a pasted clone URL never became
   `namespace/name`.
2. The token field accepted any text, so a pasted token value was silently
   forwarded and only failed at the API with a cryptic ZodError.

Additionally, the running web bundle was stale: the fix existed in source but
the Angie static bundle on :5180 was built before the change, so the UI kept
the old behavior until the web image was rebuilt.

## Solution

- `normalizeRepositoryPath()` in `packages/web/src/lib/utils.ts`: strips
  scheme+host (http/https), scp-style `git@host:`, `ssh://`, `.git`, trailing
  slashes, whitespace → `namespace/name`. Applied in both GitHub and GitLab
  connect handlers.
- Client-side guard in both connect handlers: the token field must match
  `^GITLAB_[A-Z0-9_]+$` / `^GITHUB_[A-Z0-9_]+$`; otherwise show a clear toast
  ("Enter the env variable name, not the token value") and do not send.
- 10 unit tests for the normalizer.
- Rebuilt the web service so the bundle is live.

## Prevention

- Accept the human's natural input (clone URL) and normalize client-side.
- Never accept token values in request bodies — the field is an env-var *name*.
- After changing web source, rebuild the web image (`docker compose up -d --build web`)
  — the dev-compose web serves a static bundle, not Vite HMR.
- API stays the strict last line of defense; UI should meet users halfway.
