# Stabilize ai:perf under occupied dev ports

**Date:** 2026-09-22 01:47
**Files:** `packages/web/scripts/run-perf.mjs`, `packages/web/vite.config.ts`, `packages/web/e2e/perf/utils.ts`, `packages/web/e2e/perf/dashboard-load.spec.ts`, `packages/web/e2e/perf/runtime-profiles-endpoint.spec.ts`
**Severity:** medium

## Problem

`npm run ai:validate` failed at `ai:perf` with `EADDRINUSE` on API port `3009`.
After isolating perf ports, the suite still failed with widespread `502`/timeouts
because the web dev proxy continued forwarding requests to `localhost:3009`
instead of the isolated API port.

## Root Cause

Two independent issues combined:

1. `ai:perf` started the whole dev stack on fixed default ports (`3009/5180`),
   which collided with existing local processes.
2. `packages/web/vite.config.ts` resolved `API_PORT` from `process.env.PORT`
   after loading `.env` with `override: true`, so even when perf injected a
   different port at runtime, proxy routing still pointed to `3009`.

## Solution

- Introduced isolated perf ports in `run-perf.mjs`:
  - API: `AIF_PERF_API_PORT` (default `39009`)
  - Web: `AIF_PERF_WEB_PORT` (default `35180`)
- Propagated perf env into spawned dev and Playwright processes:
  - `PORT`, `AIF_API_PORT`, `API_BASE_URL`, `AIF_E2E_API_URL`, `AIF_E2E_WS_URL`.
- Scoped perf runner to perf specs only:
  - `playwright test --config=playwright.config.ts e2e/perf`
- Updated Vite proxy resolution order:
  - `AIF_API_PORT`/`API_BASE_URL` now take precedence over default `.env` port.
- Updated perf specs/helpers to use env-driven API origin constants instead of
  hardcoded `localhost:3009` literals.

## Prevention

- Keep perf/integration runners port-isolated by default to avoid dependence on
  machine-local dev state.
- In configs that load `.env` with override, prioritize explicit runtime
  override variables for test harnesses.
- Avoid hardcoded host/port literals in perf assertions and network capture;
  route through shared env-backed constants.
