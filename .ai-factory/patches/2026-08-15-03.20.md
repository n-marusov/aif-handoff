# GitLab connect 400 ZodError: user pasted full URL and token value

**Date:** 2026-08-15 03:20
**Files:** `packages/web/src/lib/utils.ts`, `packages/web/src/components/project/ProjectSelector.tsx`, `packages/web/src/__tests__/utils.test.ts`
**Severity:** low (UX validation friction)

## Problem

Connecting a GitLab repository from the Web UI returned `400 Bad Request` with
a `ZodError`:

- `repository` `"https://gitlab.com/vedo-ecosystem/vedo-core"` → rejected: must be `namespace/name` (`/^[A-Za-z0-9_.-]+(\/[A-Za-z0-9_.-]+)+$/`).
- `tokenEnvVar` `"glpat-..."` → rejected: must be an uppercase `GITLAB_*` env var name.

The API validation was correct; the user had pasted a full clone URL into the
repository field and the token **value** into the env-var-name field.

## Root Cause

The Web UI form (`ProjectSelector.tsx`) sent the repository field verbatim
(`gitlabRepository.trim()`), so a pasted URL never became `namespace/name`.
The token field is documented as an env-var name ("The server reads the token
from this environment variable"), but the placeholder/UX did not prevent a user
from pasting the token value itself.

## Solution

- Added `normalizeRepositoryPath()` to `packages/web/src/lib/utils.ts`: strips
  `https://`/`http://` scheme+host, scp-style `git@host:`, `ssh://`, trailing
  `.git`, trailing slashes, and whitespace → `namespace/name`.
- Applied it in both `handleConnectGitHub` and `handleConnectGitLab` before
  sending, so pasting a full URL now works.
- Added 10 unit tests covering bare paths, nested groups, http(s), ssh forms,
  `.git` suffix, trailing slashes, whitespace, and empty input.

## Prevention

- Accept the human's natural input (a clone URL) and normalize server-side or
  client-side instead of demanding a strict format.
- Never accept token values in request bodies — `tokenEnvVar` must always be an
  env-var name; the value belongs in `.env`.
- The API's strict schema is the correct last line of defense; the UI should
  meet users halfway.
