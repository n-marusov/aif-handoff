# API Slash Commands Were Sent as Literal Prompts

**Date:** 2026-09-11 20:50
**Files:** packages/runtime/src/promptPolicy.ts, packages/agent/src/subagentQuery.ts, packages/agent/src/subagents/planner.ts, packages/runtime/src/__tests__/workflowSpec.test.ts, packages/agent/src/__tests__/subagentQuery.test.ts
**Severity:** high

## Problem

OpenRouter/API planner runs received `/aif-plan` as ordinary user text. Because API runtimes do not interpret local slash commands or provide workspace tools, the model could respond with an implementation-style report, fabricated `ls` output, and patch text instead of a plan-only checklist for human review.

## Root Cause

The planner supplied `fallbackSlashCommand` while also supplying an explicit `workflowSpec`. `buildWorkflowSpec` returned the explicit spec unchanged, so the fallback command was discarded. Even when the command was preserved, API transport had no slash-command interpreter: prepending the literal command was insufficient and left the model without the actual skill instructions or an explicit read-only/tool-availability contract.

## Solution

- Preserve a separately supplied fallback command when enriching an explicit workflow spec, including restoring `fallbackStrategy: "slash_command"` when the spec used `"none"`.
- Add runtime-neutral API prompt policy that expands recognized `/aif-*` commands into project skill instructions when available, with safe inline fallbacks otherwise.
- Explicitly tell API models that slash commands are workflow labels, not executable commands; they must not claim command execution or invent tool output.
- Add planner fallback metadata for normal and fix planning flows.
- Add regression tests covering the prompt policy and the complete `executeSubagentQuery` → OpenRouter SSE path.

## Prevention

- Treat slash-command fallback as a runtime-specific prompt policy, not as a command that every provider can execute.
- Test each API workflow through the resolved runtime adapter and inspect the outgoing request prompt, not only the original workflow object.
- Keep planning instructions explicitly read-only and require unchecked checklist items so plan-review artifacts cannot look like completed implementation.
