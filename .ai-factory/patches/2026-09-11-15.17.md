# Plan review commits infrastructure files and planner implements instead of planning

**Date:** 2026-09-11 15:17
**Files:** packages/agent/src/planReviewCommit.ts, packages/agent/src/subagents/planner.ts
**Severity:** high

## Problem

Three interrelated issues during plan-review flow for VCS-linked tasks:

1. **Plan review commit staged ALL dirty files (including `.ai-factory/` and `.claude/` infrastructure files)** — The `dirtyAllowed` filter on line 237 used `dirtyAbs` (all dirty paths) instead of `allowedAbs` (only permitted plan file paths), causing every dirty file to be `git add`'d and committed despite the infrastructure-prefix filtering in the product-file check.

2. **Planner produced implementation reports instead of plans** — The planner prompt instructed the model to "create or refine an implementation-ready markdown checklist plan" but did not explicitly prohibit modifying, creating, or deleting files during planning. The model interpreted "plan" as "implement", created `test.md` in the target project root, and saved an execution report as the plan document.

3. **Plan checker unable to recover** — When the plan-checker detected non-checklist content (`hasChecklist: false, looksLikeFull: false`), the local fallback (`convertBulletsToCheckboxes`) also failed because the plan was an implementation report with no convertible bullets. The bad plan was kept by default.

## Root Cause

- **`planReviewCommit.ts` line 237:** Variable misuse — `dirtyAbs` was used in the filter predicate when `allowedAbs` was intended. This is a copy-paste or refactoring error where the wrong Set was referenced.
- **`planner.ts` subagents prompt:** The prompt used passive language ("Create or refine an implementation-ready markdown checklist plan") that the model interpreted as permission to execute tasks. Missing an explicit hard constraint against file mutation during planning.
- **Plan checker fallback:** The fallback path had no recovery mechanism for completely non-plan content beyond the simple bullet-to-checkbox conversion.

## Solution

1. **Fixed `planReviewCommit.ts` line 237:** Changed `dirtyAbs` to `allowedAbs` in the `dirtyAllowed` filter. Now only the plan file (and any explicitly allowed extra paths) is staged and committed. Infrastructure files under `.ai-factory/` and `.claude/` are still tolerated as dirty (not blocking the commit) but are no longer included in the commit itself.

2. **Fixed `planner.ts` prompt:** Added explicit CRITICAL constraint: "Do NOT modify, create, or delete any files during planning. Do NOT write any code, create any new files (such as test.md), or make any changes to the project. Your ONLY task is to write a checklist plan document to @planPath." Also added: "Never mark items as completed '- [x]' — all items start unchecked."

## Prevention

- **Plan review commit:** Reviewers should verify the `dirtyAllowed` filter uses `allowedAbs` (not `dirtyAbs`) if this code is refactored.
- **Planner prompt:** The explicit "Do NOT modify/create/delete files" constraint should be preserved as a structural invariant in all planning prompts. Future prompt changes should keep this constraint prominent (near the task description, not buried).
- **Plan checker:** Consider adding a last-resort recovery that generates a minimal checklist template when the plan is entirely non-plan content (no bullets, no checkboxes).
- **Testing:** Add a test for `ensurePlanReviewCommit` that verifies infrastructure files are not staged when they are dirty.
