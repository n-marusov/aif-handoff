# OpenRouter "No models provided" — model not passed to adapter run input

**Date:** 2026-09-14 10:11
**Files:** packages/agent/src/subagentQuery.ts, packages/runtime/src/errors.ts
**Severity:** critical

## Problem

When the OpenRouter runtime adapter was used for implementing a task (skills-mode,
`useSubagents=false`), every subagent query failed with `OpenRouter error:
{"error":{"message":"No models provided","code":400}}`. The coordinator then
reverted the task status to `implementing` on each failure, causing an infinite
poll loop — the same task was picked up, failed, reverted, and picked up again
on every cycle.

The agent log showed `model: null` in the OpenRouter adapter run invocation
even though the subagent-query resolution had correctly resolved the model to
`"openai/gpt-5.3-codex"`.

## Root Cause

Two separate bugs compounded into an infinite loop:

1. **Bug 1 (root cause of "No models provided"):** In `executeSubagentQuery()`
   in `packages/agent/src/subagentQuery.ts`, the `runInput` object (line 1271)
   constructed from the resolved execution context did not include the `model`
   field. The model was correctly resolved during `resolveExecutionContext()` —
   `context.model` was set to `"openai/gpt-5.3-codex"` — but was never
   transferred to the `RuntimeRunInput` that was passed to `adapter.run()`.
   The OpenRouter adapter reads `input.model` to populate the API request body;
   since it was `undefined`, the request had no `model` field, and OpenRouter
   rejected it with `"No models provided"`.

2. **Bug 2 (infinite loop):** The error category was `"unknown"` because
   `"No models provided"` didn't match any existing pattern in
   `SHARED_FALLBACK_PATTERNS`. In the coordinator's `classifyStageError()`,
   `"unknown"` is not in `EXTERNAL_FAILURE_CATEGORIES`, so `isExternalFailure()`
   returned `false`, and the error fell through to the `revert` case — setting
   the task status back to `stage.inProgress` (`"implementing"`). The
   coordinator then picked the same task up on the next poll cycle, creating an
   infinite loop.

## Solution

1. **`packages/agent/src/subagentQuery.ts` (line 1301):** Added
   `model: context.model ?? undefined` to the `runInput` object. This passes
   the resolved model from the execution context to the adapter's `run()`
   method, so the API request body includes the correct model identifier.
   `?? undefined` ensures that `null` (no model) converts to `undefined`,
   which matches `RuntimeRunInput.model?: string`.

2. **`packages/runtime/src/errors.ts` (line 225):** Added `"no models
   provided"` to the `model_not_found` patterns in `SHARED_FALLBACK_PATTERNS`.
   If a future profile has no model configured, the error is now classified as
   `model_not_found`, which is in `NON_RETRYABLE_RUNTIME_CATEGORIES` and
   results in `blocked_external` (manual action required) rather than `revert`
   (infinite loop).

## Prevention

- The `runInput` object in `executeSubagentQuery()` should mirror all relevant
  `RuntimeRunInput` fields from the resolved context. When adding new fields to
  `RuntimeRunInput`, verify they are propagated from the execution context.
- Review the pre-existing test failures in `subagentQuery.test.ts` under the
  "model fallback policy" describe block — the 4 tests that check
  `callInput.model` were already failing before this fix, confirming the model
  was never passed through.
