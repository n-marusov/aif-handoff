# Remove accept_existing_plan and delete stale plan files before fresh planning

**Date:** 2026-09-10 22:33
**Files:**
- packages/agent/src/subagents/planner.ts
- packages/api/src/services/taskEvents.ts
- packages/shared/src/stateMachine.ts
- packages/shared/src/types.ts
- packages/web/src/components/task/useTaskDetailActions.ts

- packages/web/src/components/task/TaskDetailHeader.tsx
- packages/shared/src/__tests__/stateMachine.test.ts
**Severity:** medium

## Problem

New GitHub issue tasks in the VNC target repository loaded an unrelated old
plan from `.ai-factory/PLAN.md` even when the task had an explicit
task-specific `planPath` like `.ai-factory/plans/github-issue-3.md`.

Two root causes:

1. `clearPlanFileBeforeFreshPlanning()` only deleted the canonical plan file
   (`.ai-factory/plans/github-issue-3.md`) but NOT the generic fallback files
   (`.ai-factory/PLAN.md` and `PLAN.md`). The `/aif-plan` skill running in
   the target worktree could read `.ai-factory/PLAN.md` and use its stale
   content as the plan.

2. The `accept_existing_plan` event and its `handleAcceptExistingPlan()`
   handler allowed users to explicitly copy a plan file from disk into the
   task. When `task.planPath` fell back to the default `.ai-factory/PLAN.md`,
   this copied the stale plan. The UI offered a "Use Existing Plan" button
   in the "Plan file already exists" dialog triggered by `Start AI`.

## Root Cause

- `clearPlanFileBeforeFreshPlanning()` targeted only the resolved canonical
  plan path registered on the task. It did not sweep generic plan files
  that the runtime agent skill (aif-plan) could discover and read.
- `handleAcceptExistingPlan()` read `task.planPath || cfg.paths.plan` from
  disk and persisted its content into `task.plan`. When `planPath` fell back
  to `.ai-factory/PLAN.md`, the stale committed plan in the target repo was
  copied verbatim.

## Solution

1. **In `clearPlanFileBeforeFreshPlanning()`**: Now also deletes
   `cfg.paths.plan` (`.ai-factory/PLAN.md`) and root `PLAN.md` before fresh
   planning, preventing the runtime skill from finding stale plan content.

2. **Removed `accept_existing_plan` entirely**: The event was removed from
   `TaskEvent` type, state machine transitions, `handleAcceptExistingPlan()`
   handler, dispatch in `handleTaskEvent()`, and all UI components
   (`useTaskDetailActions`, `TaskDetail` dialog, `TaskDetailHeader` action
   buttons). Users can still see the "Plan file exists" dialog when clicking
   "Start AI", but only the "Overwrite & Re-plan" option remains — there is
   no way to accept an existing plan from the UI.

## Prevention

- Plan files in the target repository's generic fallback paths
  (`.ai-factory/PLAN.md`, `PLAN.md`) are always deleted before a fresh
  planning run, making them invisible to both `readPlanFromDisk()` and the
  runtime `/aif-plan` skill.
- No event or UI path exists to explicitly copy disk plans into a task.
- Regression test covers explicit plan path + stale `.ai-factory/PLAN.md`.
