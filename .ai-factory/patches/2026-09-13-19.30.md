## Problem

When a task selected an API-only runtime profile (e.g. OpenRouter with `openai/gpt-5.3-codex`), the implementation stage silently switched to an unconfigured Codex CLI runtime. Codex CLI then failed with `401 Unauthorized` against `wss://api.openai.com/v1/responses`. The task cycled infinitely between `implementing` and `blocked_external` because auth errors were treated as retryable external errors with random backoff.

Root causes:
1. No capability for "API returns tool_calls; local agent executes them" — `supportsWorkspaceTools` conflated native filesystem execution with API tool calling.
2. `fallbackToWorkspaceToolRuntime()` scanned the registry for any workspace-capable runtime and silently switched profiles.
3. Auth/configuration errors got random backoff instead of permanent `blocked_external`.

## Solution

### New `supportsToolCalling` capability
A distinct boolean flag indicating the adapter can return tool_calls for local execution. `supportsWorkspaceTools` remains for native workspace editing (e.g. Claude SDK, Codex CLI). API adapters set `supportsToolCalling: true`.

### New runtime-neutral types
`RuntimeToolDefinition`, `RuntimeToolCall`, `RuntimeConversationMessage` — shared by agent and adapters. `RuntimeRunInput` extended with `messages`, `tools`, `toolChoice`. `RuntimeRunResult` extended with `toolCalls`, `finishReason`.

### OpenRouter/Codex API tool protocol
Both adapters now forward `tools`, `tool_choice`, and full conversation history (assistant+tool messages) in Chat Completions requests. Non-stream and streaming paths parse `tool_calls` from responses. Streaming path accumulates fragmented `delta.tool_calls` by index.

### API tool loop in subagentQuery
When an API runtime with `supportsToolCalling` is selected for implementation: send tools definitions, execute returned tool calls locally via `WorkspaceToolExecutor`, append results, call the SAME runtime/profile again. Enforces a 20-step limit. Retains exact profile ID, runtime ID, transport, model, headers, and options across every iteration.

### Local workspace tool executor
`packages/agent/src/workspaceTools.ts` — sandboxed file operations with path security, denied directories, backup copies, regex-free unique `oldText` enforcement, and size limits.

### Structured error classification
- `errorClassifier.ts`: replaced message-pattern matching with `instanceof` checks for `RuntimeCapabilityError`, `RuntimeResolutionError`, `RuntimeValidationError`.
- `stageErrorHandler.ts`: added `"auth"` to `NON_RETRYABLE_RUNTIME_CATEGORIES` (permanent block instead of backoff). Added `findConfigurationError()` check for capability/resolution/validation errors → permanent block.
- `taskWatchdog.ts`: `releaseDueBlockedTasks()` now preserves retry count instead of resetting to zero.

### Profile validation
`isPinnedRuntimeProfileCurrent()` in `subagentQuery.ts` validates pinned selections against current DB profile state (enabled, visible to project, exact fields match). Stale pins are discarded gracefully.

## Prevention
- API-only runtimes should set `supportsToolCalling: true` instead of requiring `supportsWorkspaceTools: true` for implementation workflows.
- Registry-wide runtime fallback is now fully blocked: GUI profile selection is authoritative.
- Auth and configuration errors never get random backoff or watchdog release.
- Retry counts are preserved across watchdog releases to prevent infinite cycles.
